Executed audit of the API bootstrap + middleware + endpoint posture on
`feat/p6-production-hardening` (2026-07-28). Severity is impact-to-running-platform.

## Applied this pass

- **`trust proxy`** (correctness/security): rate limiting + request logging now attribute the real
  client IP behind a proxy. Configurable via `TRUST_PROXY_HOPS` (default 1). tsc clean.

## Recommendations (do before production — low risk)

1. **Explicit body/upload limits** — set an Express JSON limit (e.g. `100kb`–`1mb`) and Multer
   `limits.fileSize` on any upload route, so a large-payload request can't pressure memory. Verify
   the raw webhook body limit is >= the largest legitimate provider event.
2. **Edge TLS + HSTS** — enforce HTTPS redirect + HSTS at the LB; helmet already sets the HSTS
   header, but the edge must not serve plaintext.
3. **Prisma pool sizing** — set `?connection_limit=` per instance so `replicas × limit` stays under
   the managed-PG `max_connections`; add a PgBouncer in front for high fan-out.
4. **CSP for web apps** — the Next.js apps need their own CSP (separate from the API helmet default).

## Attack-matrix (run on staging — P6.8 overlap)

cross-user/cross-session booking access · cross-tenant admin · provider spoofing · provider-selection
attempt · price/currency tampering · webhook replay · signature failure · idempotency abuse ·
refund-amount tampering · compensation-type tampering · privilege escalation. Code guards make each
**expected fail-closed**; the live proof needs the staging deploy.

## Verdict

**Strong infra posture.** One correctness fix applied (`trust proxy`). No Critical/High infra-config
defect. Open items are low-risk hardening (body limits, pool sizing, edge TLS/HSTS, web CSP) +
SEC-1 dependency remediation (see DEPENDENCY-REMEDIATION.md), all tracked as pre-production gates.
