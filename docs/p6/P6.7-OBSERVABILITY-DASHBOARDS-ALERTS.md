# P6.7 — Observability: Dashboards & Alerts

Built on the metrics the app **actually exposes** (`apps/api/src/metrics/metrics.service.ts`,
`/api/metrics`, Prometheus). Every panel below references a real `etg_*` series. Thresholds are
**recommended starting points** — tune from the P6.4/P6.5 soak/load baselines, not from guesses.

## Dashboards

### D1 — Booking

| Panel                     | Query                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------- |
| Initiations / Confirms    | `rate(etg_bookings_created_total[5m])`, `rate(etg_bookings_confirmed_total[5m])`        |
| Orchestration outcome mix | `sum by (result) (rate(etg_booking_orchestration_total[5m]))`                           |
| E2E orchestration latency | `histogram_quantile(0.95, rate(etg_booking_orchestration_duration_seconds_bucket[5m]))` |
| Legacy fallback           | `rate(etg_booking_legacy_fallback_total[5m])`                                           |
| Shadow mismatch           | `rate(etg_booking_shadow_mismatch_total[5m]) / rate(etg_booking_shadow_total[5m])`      |
| GMV                       | `rate(etg_gmv_minor_total[15m])`                                                        |

### D2 — Inventory

`etg_inventory_lock_contention_total`, `etg_inventory_lock_ops_total`,
`histogram_quantile(0.95, rate(etg_inventory_lock_op_duration_seconds_bucket[5m]))`,
`etg_inventory_lock_reconcile_total`, `etg_booking_allocation_validation_total`,
`etg_inventory_sync_provider_health_total`, sync lag via `etg_inventory_sync_poll_total` vs
`etg_inventory_sync_apply_total`.

### D3 — Payments

`etg_booking_payment_void_total{outcome}`, `etg_booking_payment_refund_total{provider,outcome}`,
`histogram_quantile(0.95, rate(etg_booking_payment_refund_duration_seconds_bucket[5m]))`,
`etg_booking_payment_status_recovery_total`, `etg_booking_refund_status_recovery_total`,
`etg_booking_refund_policy_decision_total{mode,reason}`.

### D4 — Outbox

`etg_outbox_created_total`, plus the outbox health counts (pending / oldest-pending age /
retryable / dead-lettered / stale-lease) from `GET /health` and the domain-event handler duration
`etg_domain_event_handler_duration_seconds`.

### D5 — Compensation

`etg_booking_compensation_backlog{state}` (gauge), `etg_booking_compensation_oldest_ready_age_seconds`,
`etg_booking_compensation_operations_total`, `etg_booking_compensation_plans_total`. Cross-check the
counts-only `GET /health/compensation` (`void.*`, `refund.*`, dead-letter, manual-review).

### D6 — Infrastructure

`up{job=...}` (api/worker), `histogram_quantile(0.99, rate(etg_http_request_duration_seconds_bucket[5m]))`,
`rate(etg_http_requests_total{status=~"5.."}[5m])`, `histogram_quantile(0.95,
rate(etg_db_query_duration_seconds_bucket[5m]))`, plus node/redis/pg exporters (CPU, mem, connections).

## Alert rules (recommended initial thresholds — tune from baselines)

| Alert                                   | Expression (sketch)                                                                 | Initial threshold | Severity  |
| --------------------------------------- | ----------------------------------------------------------------------------------- | ----------------- | --------- |
| **Double-booking signal**               | any oversell/duplicate-confirm reconciliation class > 0                             | `> 0` for 0m      | **page**  |
| **Oversell signal**                     | allocation-drift count (health) > 0                                                 | `> 0` for 5m      | **page**  |
| Payment success without booking         | webhook succeeded but no confirmed booking (reconciliation)                         | `> 0` for 10m     | page      |
| Booking confirmed without payment       | reconciliation class                                                                | `> 0` for 10m     | page      |
| Refund completed without local finalize | `PROVIDER_REFUNDED_LOCAL_MISSING` recon                                             | `> 0` for 10m     | page      |
| Outbox backlog age                      | oldest-pending age                                                                  | `> 300s` for 10m  | warn→page |
| Compensation backlog age                | `etg_booking_compensation_oldest_ready_age_seconds`                                 | `> 900` for 15m   | warn      |
| Dead-letter growth                      | `increase(etg_booking_compensation_operations_total{outcome="dead_lettered"}[1h])`  | `> 0`             | warn      |
| Provider outage                         | `etg_inventory_sync_provider_health_total{status="down"}` / payment provider errors | sustained 5m      | page      |
| Redis outage                            | `up{job="redis"} == 0`                                                              | 1m                | page      |
| Database saturation                     | pg connections > 80% of max, or p95 query > 250ms                                   | 10m               | warn→page |
| High booking-error rate                 | 5xx rate on booking routes                                                          | `> 2%` for 5m     | page      |

Wire via `docker-compose.observability.yml` (Prometheus + Grafana already present). Alertmanager
routing (pager vs Slack) is an owner config; this spec defines **what** and **initial thresholds**,
not the notification channel.
