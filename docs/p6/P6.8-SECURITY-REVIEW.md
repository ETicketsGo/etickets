## Finding SEC-1 (High, gate) — dependency vulnerabilities

`npm audit --omit=dev`: **23 high, 33 moderate**. Triaged by runtime exposure:

**A. Runtime-relevant (server request path) — prioritize:**
`multer` (high), `@nestjs/platform-express` (high), `fast-xml-parser` (high), `google-gax` (high),
`lodash` (high), `postcss`/`next` (high — web apps). These reach untrusted input and must be
upgraded + tested individually before pilot.

**B. Build/lint tooling only (not in the server runtime path):**
`eslint*`, `@eslint/*`, `glob`, `rimraf`, `minimatch`, `brace-expansion`, `picomatch`,
`file-entry-cache`, `flat-cache`, `js-yaml`, `@next/eslint-plugin-next`. Real but **not
runtime-exploitable**; fix opportunistically.

**Remediation (do NOT blanket `npm audit fix --force` — it applies breaking major bumps):**

1. `npm audit fix` (non-breaking) first; re-run the full suite (161/1176) + both builds.
2. For residual runtime highs, bump each package deliberately (e.g. `multer`, `fast-xml-parser`)
   and run the payment/webhook/upload tests per bump.
3. Re-audit; record residual moderate/low as accepted risk with justification.

**Status: PRODUCTION GATE — not fixed in this pass** (blanket auto-fix would destabilize the
baseline right before the pilot report; each runtime bump needs isolated verification).

## Attack scenarios to run on staging (P6.8 test matrix — pending staging)

Cross-user / cross-session booking access · cross-tenant admin access · provider spoofing ·
payment-provider selection attempt · price/currency tampering · webhook replay · signature failure ·
idempotency abuse · refund-amount tampering · compensation-type tampering · admin privilege
escalation. The code-level guards above make each **expected-fail-closed**; the live proof runs
against the staging deploy (P6.1) with the request-level harness.

Code-level security posture: **strong** (server-derived money/provider, role-guarded admin,
signature-verified webhooks, parameterized SQL, tenant isolation, PII-free telemetry). One
**production gate** open: SEC-1 dependency remediation. No Critical/High **code** defect found.
