# P6.3 — Settlement & Refund-Policy Decisions (Owner Decision Record)

**This is an owner-decision document. Engineering will NOT invent business policy.** Until each
decision below is recorded with an approver + date, `BOOKING_REFUND_POLICY_MODE` **stays
`MANUAL_ONLY`** and the refund executor **fails closed** (treats settlement as uncertain → manual
review). Auto-refund cannot be enabled in production until §1 (settlement wiring) and §2 (policy
decisions) are both complete.

## 1. Settlement lookup — engineering prerequisite (P6.3 gate #1)

The refund executor currently passes `settlementStatus: undefined` (fail-closed), so even
`FULL_GROSS` resolves to manual review. To enable any automatic refund, wire an **authoritative**
settlement read into the policy context. Data already present in the schema:

- `Payment.settlementId` → `Settlement` (status lifecycle), `Payment.refundedMinor` (cumulative guard),
  `Payment.subtotalMinor` / `taxMinor` / `platformFeeMinor` / `processingFeeMinor` /
  `organizerNetMinor` (money split snapshot), `Payment.connectedAccountId` (Stripe transfer target).

Map to the policy's `settlementStatus`: `NONE`/`PENDING` (pre-settlement → refundable, funds not yet
moved) vs `IN_PROGRESS`/`COMPLETED`/`REVERSED` (post/at-settlement → **manual review**, needs
reversal/clawback). **Unknown → fail closed.** Wire this ONLY when the read is authoritative for the
active provider; do not infer settlement from payment status.

## 2. Refund policy decisions (require product + finance sign-off)

For each, record: **Decision · Approver · Date · Policy version**. Engineering encodes only what is
recorded here (as a `BOOKING_REFUND_POLICY_VERSION`), never a default.

| #    | Decision                                     | Options (no default)                                | Owner         |
| ---- | -------------------------------------------- | --------------------------------------------------- | ------------- |
| 2.1  | Full cancellation refund                     | Gross / net-of-fees / none                          | Finance       |
| 2.2  | Event-cancellation refund                    | Full gross / gross+fees / partial                   | Finance       |
| 2.3  | Convenience-fee refund                       | Refund / retain                                     | Finance       |
| 2.4  | Tax / GST treatment                          | Refund proportionally / retain / jurisdiction rule  | Finance + Tax |
| 2.5  | Add-on refund (F&B, parking)                 | Per-item / bundled / non-refundable                 | Product       |
| 2.6  | Donation refund                              | Refundable / non-refundable                         | Finance       |
| 2.7  | Cancellation windows                         | Time-tiered % / flat / none                         | Product       |
| 2.8  | No-show policy                               | Forfeit / partial                                   | Product       |
| 2.9  | Checked-in ticket                            | Never refund (current fail-closed) / exception path | Product       |
| 2.10 | Settlement reversal                          | Auto-clawback / manual finance action               | Finance       |
| 2.11 | Provider-authoritative cancellation order    | Cancel-then-refund / refund-then-cancel             | Eng+Finance   |
| 2.12 | Allocated inventory restoration after refund | Restore-and-resell / hold / never                   | Product       |

**Explicitly NOT in scope (P5 frozen):** partial refunds have no verified policy/data model — do not
implement until 2.4/2.5/2.7 are decided and a partial data model + invariants are designed (P6/P7).

## 3. Enablement checklist (all required before production auto-refund)

- [ ] §1 settlement lookup wired + tested (fail-closed on unknown).
- [ ] §2 decisions recorded with approver/date → a concrete `BOOKING_REFUND_POLICY_VERSION`.
- [ ] A production-capable provider proven idempotent-full-refund in sandbox (P6.2) — none today.
- [ ] Monitoring + alerts for `OVER_REFUND`/`DUPLICATE`/manual-review backlog (P6.7).
- [ ] Staged rollout + rollback (`AUTO_REFUND_ENABLED=false` / restore `MANUAL_ONLY`).

**Current state: MANUAL_ONLY, fail-closed. This is the correct safe default and must not change
without the above.**
